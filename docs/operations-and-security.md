# 运行、安全与事故响应

## 启动前

- 生成高熵 `ADMIN_API_KEY`，确保不将真实 `.env`、证书或密钥提交 Git。
- `compose.yaml` 中数据库密码 `POSTGRES_PASSWORD` 必须提供。部署建议采用密钥管理器，不在容器命令行或日志打印。
- 保持端口 `127.0.0.1:8000`；远程接入通过 HTTPS、SSO、WAF/限流及反向代理。
- 所有业务 API 受同一共享 API Key 保护，**无法区分操作人，生产必须升级身份认证/RBAC**。
- 当前 `create_all` 不能管理 Schema 版本，真实业务数据导入前先完成 Alembic 迁移。

## 证据规则

- 不能虚构产地、厚度、等级、价格、库存、认证、加工能力或工程案例。
- 核验接口仅检查来源引用是否存在及字段合法；**无法证明材料真实**，必须由产品/采购负责人审阅来源。
- 已生成草稿带事实快照，不会因产品后续变动自动同步。修改事实后必须重新生成草稿或发起版本修订。
- 价格/库存等时效数据应引入过期校验和订单系统真值源（P1）；目前不生成价格声明。

## 内容和渠道安全

- 第三方授权前禁止自动发布；项目不包括爬取需要登录才能访问的数据、绕过验证或批量养号行为。
- `PUBLISHED` 仅代表人工录入发布 URL 和参考凭据，**不是系统核实外部页面存在**。
- 发布应支持模拟模式、配额、每日预算、幂等键、审批撤销和撤稿接口（P1）。
- GEO 指标为人工样本，不是全平台数据；应标注模型版本、语言、时间、采样方法和统计口径。

## 事故分类与处置

| 事件 | 当前 MVP | 生产目标 |
|---|---|---|
| 误发布 | 当前无自动发布行为 | 关闭适配器、撤销内容、保留审计、通知负责人 |
| 规格错误 | 标记内容并人工修改 | 证据版本冻结、撤回影响页面、重新审核 |
| 第三方接口拒绝 | 继续使用人工交接 | 断路器 + 重试退避 + 死信队列 + 人工恢复 |
| API Key 泄露 | 立即轮换环境变量并重启 | SSO、专人权限、密钥轮换与访问溯源 |
| 数据库损坏 | 通过备份恢复 | PITR + 定期恢复演练 + RPO/RTO 定义 |
| 搜索流量下降 | 不能直接归因于一次内容发布 | 拆分站点技术、算法波动、季节性、渠道指标调查 |

## 可观测性与验收

- 开发阶段：`/health`、`/api/v1/audit-events`、pytest。
- 生产阶段：OpenTelemetry trace、任务耗时、API 配额、队列积压、失败次数、审计完整性、每篇内容的模型成本。
- 不记录客户身份证、电话完整内容、访问凭据或平台 refresh tokens 到日志。
- 如需纳入 CRM 客户信息，先明确合法基础、权限分级、访问审计和删除规则。

## 安全未完成项

当前不满足生产暴露要求：RBAC/SSO、速率限制、真实审稿人身份、Alembic 迁移、CSRF/安全头策略、自动备份、强制 HTTPS、机密管理、持续漏洞扫描等仍待实现。
