# 90 天分阶段实施方案 · 从 v0.1 MVP 到授权集成

基线：已有可运行的本地 API/控制台/测试，但平台账号信息、企业网站技术栈、产品证据资料尚未提供。此计划为**可供开发排期的目标**，不是已完成事项或排名承诺。

## Phase 0 — 首期已经交付的代码骨架

- 产品录入、字段证据核验、关键词打分和内容事实快照。
- QA / 人工审批 / 外部发布交接流程。
- Metric/GEO 人工样本导入、统计查询与审计日志。
- SQLite 本地试运行 + PostgreSQL Compose、Swagger、基础管理台、自动化单元/接口测试。

验收：`python -m pytest -q` 通过；无外部平台副作用。

## P0：第 1–2 周 —— 真正的业务数据接入

| ID | 交付任务 | 实施点 | 验收证据 |
|---|---|---|---|
| P0-01 | 官网/账号/店铺资产清查 | 当前 CMS、域名、多语言结构、站点地图、Search Console 权限 | 权限登记与可操作范围 |
| P0-02 | Product Fact v2 | 字段版本、来源文件、复核人、有效期和证据附件 | 完整审计链 |
| P0-03 | 数据导入 | CSV/Excel 导入、SKU 去重、校验与错误报告 | 含故障样本的导入测试 |
| P0-04 | 技术 SEO 基线 | 网站 URL 清单、canonical、死链、meta、索引状态 | 可复现基线报告 |
| P0-05 | 安全基线 | OIDC/SSO、RBAC、API 密钥轮换、审计备份 | 安全验收清单 |
| P0-06 | 迁移体系 | Alembic、PostgreSQL 索引/唯一约束与备份恢复 | 迁移及回滚测试 |

优先阻断项：真实产品证据、CMS 类型、账号授权范围、生产权限模型。

## P2：第 6–9 周 —— 逐个渠道适配

同一时段不宜把五个平台所有接口一起上线。按授权和业务价值排序：

1. **官网/Google**：GSC Search Analytics、页面级指标、Sitemap 监测、英文产品内容；不滥用 Indexing API。
2. **百度**：页面可抓取性、合法站长提交能力、中文业务页优化；提交/发现/收录分开记录。
3. **抖音**：已获授权的视频发布与数据接口，或维持人工交接；先验证发布权限与官方回执。
4. **国内店铺**：商品属性、标题、图片映射与店铺数据，以商家授权范围为限。
5. **国际站**：多语言商品字段映射、类目/认证校验、已授权接口和国际询盘数据。

每个适配器必须提交：授权/权限说明、错误码规范、配额限制、沙箱/回放测试、操作审计、失败恢复及禁止行为清单。

## P3：第 10–12 周 —— 评价与持续优化闭环

| ID | 任务 | 预期产物 |
|---|---|---|
| P3-01 | 有效线索定义与 CRM | 点击→询盘→有效线索→报价→订单的可追踪映射 |
| P3-02 | 周期效果分析 | 品牌/非品牌、语言、SKU、页面、渠道分层的变化趋势 |
| P3-03 | GEO 评测协议 | 固定问题集、地区/时间/模型标记、引用抽样、人工事实核验 |
| P3-04 | 优化建议器 | 基于真实指标提出页面修改任务，保留审批与效果对照 |
| P3-05 | 生产可观测性 | 链路追踪、队列失败、渠道 API 成功率、模型质量与费用 |
| P3-06 | 安全与回归测试 | E2E 测试、权限滥用测试、回滚演练与备份恢复 |

## 单人工程资源建议

- 35%：业务数据及官网 SEO（最高优先级）。
- 25%：内容生产与 QA。
- 20%：受控渠道集成。
- 10%：分析与 CRM 归因。
- 10%：测试、运维与治理。

**授权不足时主动降级**：由自动化切到 `MANUAL_HANDOFF`；在没有可靠数据时报告 `unknown`，不将臆测的 SEO 排名或 GEO 可见性写入仪表盘。

## Release Gate

- Gate 1 数据：真实性、来源与负责人核对；拒绝无依据规格。
- Gate 2 系统：迁移、安全、恢复、发布审批和幂等测试通过。
- Gate 3 站点：测试环境先上线，检查收录影响和 canonical/hreflang。
- Gate 4 渠道：官方接口和账号授权通过，批准限额与回滚。
- Gate 5 增长：有可复现的前后对比、非品牌分层与有效询盘口径。

如果以上条件尚未满足，即使自动化测试通过，也不能宣称生产就绪。
