# 架构决策记录

## ADR-001：首期采用模块化单体，而不是微服务

**决策**：采用 FastAPI + SQLAlchemy + PostgreSQL（本地 SQLite）+ 领域化目录。
**原因**：单人/小团队开发，业务需求仍在验证，微服务增加网络与数据一致性成本。
**升级触发**：发布量、爬取任务、模型推理及组织边界独立增长时，通过队列和独立 worker 拆分。

## ADR-002：不默认连接 LLM

**决策**：离线模板内容引擎先完成事实与状态验证。LangGraph + LLM 在第二阶段单独接入。
**原因**：石材参数/工程信息容易产生高风险事实幻觉；真实企业证据与审核流程尚未提供。
**升级触发**：真实文档入库、事实检索准确率和 QA 基线建立，允许受限提示词和模型替换。

## ADR-003：外部发布默认人工交接

**决策**：`MANUAL_HANDOFF`/`READ_ONLY_ANALYTICS` 为默认能力，不接受“无 OAuth 也能发”的非官方绕过逻辑。
**原因**：平台授权未知；误发内容与账号处罚可能影响主营业务。
**升级触发**：完成官方授权、沙箱验收、幂等及撤销机制后，单平台单账号启用。

## ADR-004：发布、收录、搜索曝光独立建模

**决策**：不得以发布交接成功代替收录或排名结果。
**原因**：搜索索引/推荐和第三方平台排序不在本站控制范围。
**升级触发**：获取官方测量数据后扩展 `IndexStatus` 与 `SearchObservation` 实体。

## ADR-005：事实核验与写作模型解耦

**决策**：任何生成文本必须使用事实快照，由业务审核和强约束 QA 决定是否允许发布。
**原因**：不能把语言模型生成的文本视为有证据支持的产品数据库。
**升级触发**：建设字段级 evidence、文档哈希、签名复核及内容版本差异比较。
